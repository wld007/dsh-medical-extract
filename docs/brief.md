# 病历文书提取 · dsh-medical-extract

> Medical Document Extraction（chart abstraction）。DeepSeek Harness 插件。
> **通用插件**：给一份提取模板（字段清单），从任意病历文书里把这些字段提取出来，每个值带逐字原文出处。
> 插件内置 7 个病种模板（抑郁障碍、急性缺血性卒中、阿尔茨海默病与认知障碍、心力衰竭、2 型糖尿病、慢性肾脏病与血液透析、非小细胞肺癌），也可以自建；病种内容只在模板里，不在插件代码里。

## 1. 定位

| | 病历事件还原（`event`） | 病历文书提取（本插件，`extract`） |
|---|---|---|
| 提取什么 | 全部：每处提及都记 | 只提取模板里的字段 |
| 单位 | 一位病人 | 一份文书（7,000 万份级） |
| 产物 | 事件包 | 宽表＋证据长表 |
| 依赖 | — | **不依赖**事件包，直接读文书 |

规模目标：**7,489 万份文书**一个批次跑完，能断点续跑、能并行、改模板后只重算受影响的部分。

## 2. 核心概念

- **文书（document）**：一份病历文本，带病人、就诊、文书类型、写成时间、栏目（主诉、现病史……）。由数据源层从导出里读出。
- **模板（template）**：字段清单，带版本。每个字段写明定义、值类型、来源文书和栏目、召回词、规则、汇总规则、粒度、值域。格式见 `docs/template.md`。
- **值（value）**：从一份文书里提取到的一个字段值。必须带引语（原文逐字片段）及其在文书里的起止位置，由插件自己在原文中定位。
- **断言（assertion）**：每个值的语境：`阳性`／`否认`／`可疑`／`既往`／`家族`／`计划`。只有"阳性且当前"算"有"。
- **汇总（rollup）**：按字段的粒度（文书／就诊／病人／时间点）和汇总规则（首次、末次、全部、最大……）把值合并成宽表的格子；同一格子里互相矛盾的值登记为冲突，不自动选边。

## 3. 产线

产线页 2.5D 场景里一栋楼一道工序。

| 楼 | 做什么 | 产出 | 模型 | 验收门 |
|---|---|---|---|---|
| E0 模板 | 载入并校验模板：字段的定义、值类型、选项、值域、粒度，以及适用的文书类型和栏目 | 字段规格 | — | 模板校验通过 |
| E1 读入·清洗 | 识别格式，按表判定类别：文书表读入，检验、医嘱、处方、诊断明细、收费等结构化表只取人口与就诊（结构化数据的映射不在本插件做，见 HL7 标准化），忽略的表不读；定不了类别的按叙述性兜底（`lib/source/narrative.js`）。清洗（`lib/source/clean.js`）：解码嵌入内容（base64、XML／HTML、RTF），去掉图片等二进制（整段 base64 的图片／PDF、HTML 里的 <img> 与 data URI、RTF 的 \pict 与嵌入对象、文中的长 base64 串；不做 OCR，只计数），去掉导出残留的 Java 对象乱码，丢掉占位的字段值（null、-），切栏目，剔除清洗后各栏目不到 2 个汉字的空壳文书 | 干净的文书与栏目；报告给出空壳与清洗计数 | 仅格式识别 | — |
| E2 分派 | 按文书类型和栏目决定每份文书要提取哪些字段，**不看关键词**；字段按模板顺序每组 `readMaxFields`（30）个，长于 `readMaxChars`（6000 字）的文书按栏目边界、再按句末分段（`lib/engine/dispatch.js`） | 提取任务＝文书（或其中一段）× 一组字段，编号稳定 | — | — |
| E3 提取 | 提取模型通读每个任务，返回值、断言、逐字引语；插件在本段原文里定位引语，对不上的丢弃；限定了栏目的字段，引语要落在这些栏目里。模板写了明确规则（`rules`）的字段，规则另出一票（规则票）对照：一致记 `model+rule`，不一致进人工复核。内容相同的任务只调一次模型 | 带引语、起止位置、出处的值 | 提取模型 | ① 引语逐字一致 |
| E4 归一 | 单位、日期、选项写法统一；按类型、选项、值域校验 | 规范值 | — | ② 值在类型、选项、值域之内 |
| E5 汇总 | 按粒度、汇总规则合并成格；派生字段（年龄、减分率……）；冲突登记 | 宽表、时间点长表、冲突表 | — | ③ 每个格子能回溯到值、每个值能回溯到原文 |
| E6 核验·复核 | 核验模型抽样（按文书 `verifySampleRate`，另保证每个有值字段至少 `verifyMinPerField` 次），对同样的任务背靠背通读；按字段比文书级结论（两边都"未提及"不计）；核验分歧与规则票不一致进人工复核；裁定按稳定编号存，重跑沿用 | 一致率与复核单 | 核验模型 | ④ 各字段一致率 ≥ 阈值（默认 0.9） |
| E7 交付 | 宽表、证据长表、冲突表、报告；源文件只读核对 | 交付目录 | — | — |

**必须有模型**：本插件只用模型从文书里提取，没有配置提取模型（`baseURL`、`model`）不能开始批次（页面的「新批次」按钮、Agent 工具、`/extract` 命令都会拒绝并提示去设置）。没有"仅规则"模式，也没有规则兜底：模型端点出错的调用记失败，批次可以取消后用「继续」接着跑，已完成的分片和模型调用直接复用。

**模式**（设置项 `extractMode`）：
- `hybrid`（默认）：模型通读＋规则票。
- `model`：模型通读，不出规则票。

规则引擎只做两件事：规则票，以及 `model: never` 的字段（关键词定位后规则定值，定不了的标"待定"）。召回词只给这两处和成本开关 `skipNoKeyword`（默认关：一份文书里一个模板关键词都没有就整份跳过——关键词漏掉的写法模型也就看不到，只在全量成本吃紧时打开）用。

## 4. 规模设计（7,000 万份）

- **流式读入**：文件逐个读，不一次性载入。
- **分片**：文书按稳定顺序切成分片（默认 2,000 份一片）。分片是调度、断点、输出的单位；记录库 `shards` 表记每片状态，继续处理时跳过已完成的分片。
- **并行**：多个工作线程各处理一片（默认 CPU 数−1）；模型请求全局限流（`modelConcurrency`）。
- **模型去重缓存**：缓存键＝sha256(模型＋提示)，同一输出根目录下各批次复用。模板化、复制粘贴的文书大量重复，去重直接省掉调用。
- **只读文书、先清洗**：结构化记录不进提取，空壳文书剔除，送模型的是干净的文书文本；长文书按栏目分段，字段分组，每个任务的提示大小有上限。
- **汇总分桶**：证据先按病人哈希分到 K 个桶文件，再逐桶在内存里汇总，内存不随总量增长。
- **改模板增量重算**：字段签名（定义＋规则＋提示）变了的字段才重算；没变的字段沿用上一批结果（M2）。

## 5. 交付

输出根目录 `<outputRoot>/<输入名>/`：

| 文件 | 内容 |
|---|---|
| `manifest.json` | 格式版本、插件版本、模板 id 与版本、批次、计数、验收门 |
| `wide_patient.csv`、`wide_encounter.csv` | 宽表：一行一位病人／一次就诊；每个字段一列（多值用 `；` 连接），另有 `<字段>__n`（证据数）列 |
| `timepoints.csv` | 时间点级字段的长表（量表、用药……）：病人、就诊、字段、值、时间 |
| `evidence/part-NNNNN.ndjson.gz` | 证据长表：每个值一行（文书、字段、值、断言、引语、起止、栏目、写成时间、出处：规则编号或模型） |
| `conflicts.csv` | 冲突：格子、各方值与证据 |
| `result.xlsx` | 小批次（≤ 20 万行）时附一份 Excel |

记录放 `_records/`：`records.sqlite`（批次、分片、模型缓存、调用流水、人工裁定）、`runs/<runId>/report.md|json`。

## 6. 原则（沿用插件家族 `../dsh-medical-event/docs/family.md`）

- 绝不修改输入；运行前后核对源文件。
- 病历内容只发往设置里配置的模型端点；Agent 工具不能选端点、模型、Key。
- 每个值都回得到原文；模型给的位置一律不信。
- 不做补全：没写就是"未提及"，不推断。
- 编号稳定：值＝文书编号＋字段＋起止派生；格子＝粒度键＋字段派生。
- 支持截至时刻（`asOf`）：只用此刻以前写成的文书。
- 通用：插件里不写死任何病种；病种内容全部在模板里。

## 8. 分期

- **M1**：模板格式与校验、数据源（p_doc＋通用）、分片与断点、规则召回与提取、模型提取与引语核对、断言、汇总、交付、Agent 工具与命令、产线页；内置病种模板＋虚构文书端到端。
- **M2**：抽样核验与复核页、模型起草模板、增量重算、宽表／原文标注页。
- **M3**：金标准评测（按字段 P/R/F1）、规则改进建议。
